Unit 5 · Complexity Foundations

Fast and Slow Algorithms: Growth Rates & Tractability

In algorithm design, execution speed is not measured in seconds, but in how running time scales as input size n grows. We classify problems into two worlds:

  • Tractable (Polynomial Time): Algorithms with time complexity bounded by a polynomial: O(n), O(n log n), O(n²), O(n³). Even for large inputs (n = 100,000), modern processors complete in milliseconds or seconds.
  • Intractable (Exponential Time): Algorithms requiring O(2ⁿ), O(3ⁿ), O(n!) steps. While they run fine for n = 15, an input of n = 50 requires more steps than seconds elapsed since the Big Bang!
In One Line: "Polynomial" (nᶜ) means practical and scalable. "Exponential" (2ⁿ) means it hits a computational brick wall the moment n exceeds 40.
💡 Real-Life Analogy: Intercity Train vs Rocket to the Edge of the Galaxy
If an input of n=10 takes 1 second, increasing n to 50 on an O(n²) algorithm takes 25 seconds (a pleasant train commute). On an O(2ⁿ) algorithm, it takes over 13 days. At n=60, it takes 365 centuries!

Unit 5 · Foundations

Decision Problems vs Optimization Problems

Theoretical computer science and NP-completeness exclusively analyze Decision Problems: problems whose output is strictly YES or NO. In industry, we usually care about Optimization Problems (finding the best tour, lowest cost, or highest profit).

Decision Problem

Answers a binary question: "Does there exist a solution with value ≤ k (or ≥ k)?"

Example: "Is there a TSP tour of length ≤ 500 km?"

Optimization Problem

Finds the absolute optimal configuration (minimum cost or maximum profit).

Example: "Find the tour with the minimum total distance."

Why Complexity Theory Uses Decision Problems:
  • An optimization problem is at least as hard as its decision version. If you can find the minimum tour cost in polynomial time, you can answer "is cost ≤ k?" in O(1) comparison.
  • Conversely, using binary search on k, a polynomial decision solver can solve the optimization problem in polynomial time!
  • Therefore, proving the decision problem is NP-hard automatically proves the optimization problem is NP-hard.
💡 Real-Life Analogy: Buying a Laptop
"Can I buy a laptop with 16GB RAM for under Rs 50,000?" is a Decision Problem. "Find the cheapest laptop in the market with 16GB RAM" is an Optimization Problem.

Unit 5 · Complexity Theory

Deterministic vs Non-Deterministic Algorithms & Certificates

To define the class NP, we compare two theoretical computing paradigms:

  • Deterministic Algorithm: At each step, given the current state and input, there is exactly one unique next operation. This models real computers.
  • Non-Deterministic Algorithm: Consists of two stages:
    1. Guessing stage: Magically generates a candidate certificate / solution string c in O(1) time using a special choice() primitive.
    2. Verification stage: Runs a deterministic polynomial algorithm V(x, c) to verify if the candidate solves the problem. If ANY guess produces a YES, the algorithm accepts!
What is a Certificate? A certificate (witness or proof) is a piece of evidence that allows a verifier to confirm a YES-instance in polynomial time. For Sudoku, the certificate is the completed grid. For Hamiltonian Cycle, it is the sequence of vertices in the cycle.

Unit 5 · The Big Picture

P, NP, NP-Hard, and NP-Complete

This is the most frequently repeated topic across KIIT end-semester question papers (appearing in 17 of 32 exam questions!). Memorize the four exact definitions:

Class P

Decision problems that can be SOLVED in polynomial time by a deterministic algorithm.

Examples: Dijkstra Shortest Path, Kruskal/Prim MST, MergeSort, 2-SAT, Cycle Detection.

Class NP

Decision problems whose YES-instance can be VERIFIED in polynomial time given a certificate. P ⊆ NP.

Examples: 3-SAT, Clique, Hamiltonian Cycle, Subset Sum, 0/1 Knapsack decision.

Class NP-Hard

Problems at least as hard as every problem in NP. Every problem in NP polynomial-time reduces to it. Need not be in NP.

Examples: Halting Problem (undecidable), Optimization TSP.

Class NP-Complete (NPC)

The hardest problems in NP: NPC = NP ∩ NP-hard. Solvable in poly time non-deterministically.

Examples: Circuit-SAT (Cook's theorem), 3-SAT, Vertex Cover, Clique, TSP decision.

Unit 5 · Polynomial Reductions

Polynomial Reductions (A ≤ₚ B) & The Direction Trap

A polynomial-time reduction A ≤ₚ B (read "A reduces to B") is an algorithm that converts an instance x of problem A into an instance f(x) of problem B in polynomial time, such that:

x ∈ A ⟺ f(x) ∈ B (YES maps to YES, NO maps to NO)

Core Intuition: A ≤ₚ B means "Problem A is NO HARDER than problem B". If you have a fast subroutine to solve B, you can solve A in fast time!

⚠️ THE DIRECTION TRAP (Spring 2023 Q1c(ii))
To prove that a new problem X is NP-hard, you MUST reduce a known NP-hard problem K to X:
K_known_hard ≤ₚ X_new
Reducing X ≤ₚ K proves NOTHING about the hardness of X! (A trivial problem like 2+2=4 reduces to 3-SAT, but that doesn't make addition hard!).

Unit 5 · Foundational Problems

Cook's Theorem, SAT and 3-CNF-SAT

In 1971, Stephen Cook proved the monumental Cook-Levin Theorem: Boolean Satisfiability (SAT) is NP-complete. Because this was the very first NP-complete problem, all subsequent NP-completeness proofs branch out from SAT.

Terminology:

  • Literal: A boolean variable x or its negation ≠g x.
  • Clause: An OR (∨) of literals: (x_1 ∨ ≠g x_2 ∨ x_3).
  • CNF (Conjunctive Normal Form): An AND (∧) of clauses.
  • 3-CNF-SAT: A CNF formula where every clause has exactly 3 literals.
2-SAT vs 3-SAT: The Razor's Edge!
• 2-SAT (2 literals per clause) is in P! It is solvable in linear O(V+E) time using an implication graph and strongly connected components (SCC).
• 3-SAT (3 literals per clause) jumps immediately to NP-Complete!

Unit 5 · The Equivalence Triad

Clique, Independent Set, and Vertex Cover

These three classic graph problems form an intimately connected family. Understanding their complement mapping makes reduction proofs effortless:

  • Clique: A subset of vertices S ⊆ V where every pair is joined by an edge (everyone knows everyone).
  • Independent Set (IS): A subset of vertices S ⊆ V where no two vertices share an edge (no one knows each other).
  • Vertex Cover (VC): A subset of vertices C ⊆ V such that every edge in E has at least one endpoint in C.
The Fundamental Theorem of Complements:
For any graph G = (V, E) with |V| = n vertices and its complement graph Ḡ = (V, Ē):
  1. S is an Independent Set in G ⟺ S is a Clique in Ḡ.
  2. S is a Vertex Cover in G ⟺ V \ S is an Independent Set in G.
  3. Therefore, G has a clique of size k ⟺ Ḡ has a vertex cover of size n - k!

Unit 5 · NP-Complete Reductions

Hamiltonian Cycle & Travelling Salesperson Problem

Hamiltonian Cycle (HC)

Given graph G=(V,E), does there exist a simple cycle visiting every vertex exactly once and returning to start? (NP-complete).

Do not confuse with Euler Tour (visits every edge once), which is easily solvable in O(E) in class P!

Decision TSP

Given complete graph with edge weights c(u,v) and integer k, is there a tour visiting all cities with total cost ≤ k? (NP-complete).

The Standard Exam Reduction Proof: HC ≤ₚ TSP (Autumn 2024 Q7b - 5 Marks)
  1. Construct complete graph G' on the same vertices V:
    For every pair of vertices (u, v):
    • If (u, v) ∈ E (original edge): set cost c(u, v) = 1 (or 0)
    • If (u, v) ∉ E (non-edge): set cost c(u, v) = 2 (or 1)
    • Set budget threshold k = n (or 0).
  2. Correctness:
    • If G has an HC, the same cycle in G' uses n edges of cost 1 ⟹ Total cost = n ≤ k.
    • If G' has a tour of cost ≤ n, since all edges cost ≥ 1, every edge in the tour must cost exactly 1. Hence, the tour uses only original edges of G, yielding a valid Hamiltonian Cycle!

Unit 6 · Coping Strategies

Six Practical Ways of Handling NP-Complete Problems

In industry and exams (Autumn 2023 Q7a), when a problem is NP-complete, you cannot simply give up. You apply one of six established strategies:

1. Approximation Algorithms

Polynomial-time algorithms that guarantee a solution within a provable factor ρ of the optimal answer.

Examples: 2-approx Vertex Cover, 2-approx Metric TSP.

2. Heuristics

Intuitive rules of thumb that perform well in practice on typical data, but have no mathematical worst-case guarantee.

Examples: Nearest Neighbor for TSP, Greedy search, Simulated Annealing.

3. Special Cases & Restrictions

Restricting input structures to domains where the problem becomes polynomial.

Examples: Vertex cover on trees (dynamic programming in O(n)), 2-SAT (linear time).

4. Dynamic Programming (Small n)

Exact exponential algorithms that replace brute-force O(n!) with much faster exponential time.

Examples: Held-Karp algorithm for TSP in O(n² 2ⁿ), 0/1 Knapsack pseudo-polynomial DP.

5. Backtracking & Branch and Bound

Systematically searches the solution tree while aggressively pruning branches that cannot beat the current upper/lower bound.

Examples: Branch and bound for TSP, 0/1 Knapsack, SAT solvers (CDCL).

6. Randomized Algorithms

Tosses coins to escape local minima or find high-probability good answers.

Examples: Random restarts, Monte Carlo algorithms, Karger's Min-Cut.

Unit 6 · Approximation Algorithms

Approximation Algorithms: Vertex Cover & Metric TSP

An algorithm has an approximation ratio ρ if for all inputs:

max(C / C*, C* / C) ≤ ρ
For minimization problems, Cost(Algo) ≤ ρ · Cost(OPT).

1. Vertex Cover: 2-Approximation via Maximal Matching

APPROX-VERTEX-COVER(G):
1. C = empty set
2. M = empty set (matching)
3. while there are edges in E:
4.     pick any arbitrary edge (u, v) in E
5.     add u and v to C
6.     add (u, v) to M
7.     remove all edges incident to u or v from E
8. return C
Why the Ratio is At Most 2:
  • The edges picked in M share no endpoints (they form a matching).
  • Any valid vertex cover (including optimal C^*) MUST pick at least one endpoint from each edge in M. Hence, |C^*| ≥ |M|.
  • Our algorithm adds both endpoints: |C| = 2|M|.
  • Therefore: |C| = 2|M| ≤ 2|C^*|. The ratio is strictly ≤ 2!

2. Metric TSP: 2-Approximation via MST & Preorder Walk

Requires the Triangle Inequality: c(u, w) ≤ c(u, v) + c(v, w) for all cities. Without the triangle inequality, general TSP cannot be approximated within ANY constant factor ρ unless P = NP!

Unit 6 · Amortized Analysis

Amortized Analysis: The Aggregate Method

Amortized analysis guarantees the average performance of each operation in the worst-case sequence of n operations. Unlike average-case analysis, NO probability or random inputs are involved: it is a deterministic guarantee on any sequence!

💡 Real-Life Analogy: Annual Gym Membership
Paying Rs 12,000 once a year feels like a huge single expense (expensive worst-case operation). But spread over 12 months, it is Rs 1,000/month. The big cost is amortized over the cheap months!

Case 1: The Binary Counter (Increment)

In an k-bit counter, incrementing 0111 to 1000 flips 4 bits, which costs O(k). But over n increments:

Total Flips = ∑(i=0 to ⌊log₂ n⌋) ⌊n/2ⁱ⌋ < n · ∑(i=0 to ∞) (1/2ⁱ) = 2n
Amortized cost per increment = T(n)/n < 2n/n = 2 = O(1)!

Case 2: The 2ᵏ Operation Cost Question (Autumn 2024 Q5b - 5 Marks)

Problem Statement: Operation i costs i if i is a power of 2, and 1 otherwise. Show amortized cost is O(1).
Proof:
1. Sum of expensive operations: 1 + 2 + 4 + 8 + ... + 2ᵐ = 2ᵐ⁺¹ - 1 < 2n.
2. Sum of cheap operations: at most n operations costing 1 each ≤ n.
3. Total cost T(n) < 2n + n = 3n.
4. Amortized cost = T(n)/n < 3n/n ≤ 3 = O(1).

Unit 6 · Amortized Analysis

Accounting Method, Piggy Banks, & The Shopkeeper Question

In the Accounting Method, we charge each operation an amortized fee ĉᵢ:

  • If ĉᵢ > c_i (actual cost), the excess is deposited into a bank account (credit) associated with specific data items.
  • If ĉᵢ < c_i, the deficit is withdrawn from the bank account to pay for the expensive operation.
  • Crucial Invariant: The bank balance must NEVER go negative at any step!
    ∑(i=1 to n) ĉᵢ − ∑(i=1 to n) cᵢ ≥ 0 ⟹ Total Actual Cost ≤ ∑(i=1 to n) ĉᵢ

Unit 6 · Randomized Algorithms

Randomized Algorithms: Las Vegas vs Monte Carlo

A randomized algorithm tosses coins during execution. This prevents an adversary from designing a fixed worst-case input. There are two fundamentally distinct types:

Las Vegas Algorithm

  • Correctness: ALWAYS produces the 100% correct answer upon termination.
  • Running Time: Random variable (we compute the expected time).
  • If Unlucky: Simply runs longer (never outputs a wrong answer).
  • Examples: Randomized Quicksort, Randomized Selection (Quickselect).

Monte Carlo Algorithm

  • Correctness: May output an incorrect answer with small probability ε.
  • Running Time: Fixed / deterministic bound.
  • Error Reduction: Repeating k times shrinks error to ε^k (e.g. (1/2)ᵏ or (1/4)ᵏ).
  • Examples: Miller-Rabin Primality Test, Monte Carlo π Estimation, Karger's Min-Cut.

Unit 6 · Randomized Quicksort

Randomized Quicksort & The Ramesh vs Suresh Showdown

Deterministic Quicksort with the last element as pivot degrades to Θ(n²) on already-sorted arrays. Randomized Quicksort swaps a uniformly chosen random element with the last element before calling PARTITION.

Expected Time Derivation:
E[T(n)] = (2/n) · ∑(k=0 to n−1) E[T(k)] + cn = Θ(n log n) ≈ 2n ln n ≈ 1.39 n log₂ n
Good Splits Intuition: With probability 1/2, the pivot lands in the middle half of elements (a split no worse than 3n/4). On average, every 2 levels shrinks problem size to 3/4 ⟹ ≈ 2.4 log₂ n levels, with O(n) work per level ⟹ O(n log n).
🎯 THE FAMOUS EXAM TRICK: Ramesh vs Suresh (Autumn 2024 Q6b - 5 Marks)
Question: Ramesh picks the last element as pivot. Suresh picks a random element as pivot. Whose algorithm has the lesser worst-case time complexity? Prove.
Answer: NEITHER! BOTH HAVE WORST-CASE TIME COMPLEXITY Θ(n²)!
Proof: For Suresh, there exists a tiny probability sequence of random draws that picks the maximum or minimum element at every single partition step. Under that unlucky sequence, Suresh's recurrence is also T(n) = T(n-1) + n = Θ(n²). Randomization improves the expected time to O(n log n) on ALL inputs, but does NOT alter the mathematical worst case!

Unit 7 · High-Yield Summary

One-Page Exam-Night Master Cheat Sheet

Amortized Analysis

  • Idea: Guaranteed worst-case average over n operations. No probability!
  • Aggregate: T(n)/n. Stack Multipop ≤ 2n/n = O(1). Binary Counter < 2n/n = O(1).
  • Accounting: ∑ ĉᵢ ≥ ∑ c_i (bank ≥ 0). Doubling array: charge Rs 5 (Rs 2 write, Rs 3 bank).
  • Push Digits at 2ᵏ: updates cost i-1 at powers of 2. Total < 3n ⟹ O(1).

Randomized Algorithms

  • Las Vegas: ALWAYS correct output; time is a random variable. (Randomized Quicksort).
  • Monte Carlo: Bounded time; small error probability ε. Repeat k times → ε^k. (Miller-Rabin, π darts).
  • Rand Quicksort: Expected O(n log n) ≈ 2n ln n. Worst case is still O(n²).
  • Ramesh vs Suresh: BOTH have Θ(n²) worst case! Random pivot improves expected time only.

Complexity Classes

  • P: Solvable in polynomial time deterministically. (Dijkstra, Kruskal, 2-SAT).
  • NP: Verifiable in polynomial time with certificate. P ⊆ NP.
  • NP-Hard: Every problem in NP reduces to it. (Halting problem, TSP optimization).
  • NP-Complete: In NP and NP-Hard. First problem: Circuit-SAT (Cook's theorem).
  • If ANY NPC problem gets poly solution: P = NP.

Reductions & The Famous Chain

  • Reduction A ≤ₚ B: B in P ⟹ A in P; A NP-hard ⟹ B NP-hard.
  • Direction Trap: Known NP-hard ≤ₚ New proves New is NP-hard.
  • Chain: Circuit-SAT → SAT → 3-SAT → Clique → Vertex Cover → HC → TSP.
  • Triad: Clique in G ⟺ Indep Set in Ḡ ⟺ Vertex Cover of size n-k in Ḡ.

Approximations

  • Vertex Cover 2-Approx: Maximal matching edges M, cover C = 2|M|. Since |OPT| ≥ |M| ⟹ |C| ≤ 2 · |OPT|.
  • Metric TSP 2-Approx: Prim/Kruskal MST → full walk (2 · MST) → preorder shortcutting. Cost ≤ 2 · MST ≤ 2 · OPT.
  • Christofides Algorithm: 1.5-approximation for metric TSP (MST + minimum weight perfect matching on odd-degree vertices).
  • General TSP: Has NO constant factor approximation unless P = NP.

Verification Algorithms

  • Clique ∈ NP: Certificate is set of k vertices. Check all C(k, 2) pairs share an edge. Time O(k²) ≤ O(n²).
  • TSP ∈ NP: Certificate is vertex sequence. Check all n visited and sum weights ≤ k. Time O(n).
  • Vertex Cover ∈ NP: Certificate is k vertices. Check all E edges touched. Time O(E).

Ultimate 1-Page Cheat Sheet

Everything you need to know for DAA Units 5 & 6 compressed onto a single page. High-yield formulas, reduction directions, approximations, and verification algorithms.

Amortized Analysis

  • Definition: Guaranteed average cost per operation over any worst-case sequence of n operations. (No probability involved!).
  • Aggregate Method: Find total cost T(n) for n operations, divide: T(n)/n.
  • Binary Counter: Bit i flips ⌊n/2ⁱ⌋ times. Total flips < 2n. Amortized cost < 2 = O(1).
  • Accounting Method: Assign amortized charge ĉ_i. Difference ĉ_i - c_i stored as credit in bank. Invariant: Bank balance ≥ 0 always!
  • Doubling Array: Charge Rs 5 (Rs 2 write, Rs 3 bank). Bank pays all copy spikes. Amortized cost O(1).
  • Push Digits at 2ᵏ: Updates cost i-1 at powers of 2. Total cost < 3n ⟹ O(1).

Randomized Algorithms

  • Las Vegas: ALWAYS correct result; running time is a random variable. Example: Randomized Quicksort, Quickselect.
  • Monte Carlo: Deterministic/bounded running time; small error probability ε. Repeat k independent runs to shrink error to ε^k. Example: Miller-Rabin, π estimation.
  • Rand Quicksort: Expected comparisons ≈ 2n ln n ≈ 1.39 n log₂ n = Θ(n log n).
  • Ramesh vs Suresh Trap: BOTH algorithms have worst-case Θ(n²)! Randomization does not change the worst-case bound; it makes the worst-case exponentially improbable.

Complexity Classes

  • P: Decision problems solvable in deterministic polynomial time O(nᶜ). (Dijkstra, Kruskal, 2-SAT).
  • NP: Decision problems verifiable in deterministic polynomial time given a certificate. P ⊆ NP.
  • NP-Hard: At least as hard as every problem in NP. (Halting problem, Optimization TSP).
  • NP-Complete (NPC): Hardest problems in NP (NPC = NP ∩ NP-hard). Cook's theorem: Circuit-SAT was first NPC.
  • If ANY NPC problem gets a polynomial solution: P = NP.

Reduction Rules (A ≤p B)

  • Rule 1: B ∈ P ⟹ A ∈ P. (If easy on right, easy on left).
  • Rule 2: A is NP-hard ⟹ B is NP-hard. (Hardness moves right).
  • Rule 3 (TRAP): B is NP-hard ⟹ NOTHING about A.
  • Rule 4 (TRAP): A ∈ P ⟹ NOTHING about B.
  • Rule 5: B ∈ NP ⟹ A ∈ NP.
  • Rule 6: A ∈ NPC and B ∈ NP ⟹ B ∈ NPC.
  • Chain: Circuit-SAT ➔ SAT ➔ 3-SAT ➔ Clique ➔ Vertex Cover ➔ HC ➔ TSP.

Approximation Algorithms

  • Ratio ρ: Cost(Algo) ≤ ρ · Cost(OPT) for minimization.
  • Vertex Cover 2-Approx: Pick maximal matching edges M, add both endpoints to C = 2|M|. Since |OPT| ≥ |M| ⟹ |C| ≤ 2 · |OPT|.
  • Metric TSP 2-Approx: Compute Prim/Kruskal MST T ⟹ full tree walk 2 · MST ⟹ preorder shortcut tour. Tour ≤ 2 · MST ≤ 2 · OPT.
  • Christofides Algorithm: 1.5-approximation for metric TSP using MST + minimum-weight perfect matching on odd-degree vertices.
  • General TSP: Has NO constant-factor approximation unless P = NP.

Verification Algorithms

  • Clique ∈ NP: Certificate = subset S of k vertices. Check |S| = k and check all k(k-1)/2 pairs share an edge. Time O(k²) ≤ O(n²).
  • Decision TSP ∈ NP: Certificate = sequence of n cities. Check all cities distinct, sum n edge costs, check ≤ k. Time O(n).
  • Vertex Cover ∈ NP: Certificate = subset of k vertices. Check all E edges have at least one endpoint in S. Time O(E).
  • 3-SAT ∈ NP: Certificate = truth assignment to variables. Evaluate all m clauses. Time O(m).
